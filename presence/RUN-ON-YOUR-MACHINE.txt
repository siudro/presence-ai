PRESENCE AI — how to run it on your Mac
=======================================

Three steps. That's it.


STEP 1 — Open Terminal and go into the folder
---------------------------------------------
If you extracted it to Downloads:

    cd ~/Downloads/presence

(If your folder is somewhere else, type "cd " then drag the folder into the
Terminal window and press Enter.)


STEP 2 — Start it
-----------------
    python3 app.py

You should see:

    [presence] PRESENCE AI measuring tool on http://0.0.0.0:8080

Leave this window open. That window IS the website.


STEP 3 — Open the page
----------------------
In your browser go to:

    http://localhost:8080

IMPORTANT: use that address. Do NOT open index.html from Finder — that gives
you a file:// address and the microphone and server features will not work.


FIRST USE
---------
1. Tap the gear icon (top right) to open Settings.
2. Choose your language.
3. Paste your Cohere key into the API key box.
4. Tap Save settings.
5. Tap Start and speak.

The transcript appears on screen as you talk.


ADDING AN AI CHAT KEY (optional, and FREE)
-------------------------------------------
The app works without this. With it, the coach chat answers with a
real language model instead of the built-in rules.

Two different keys exist, and they are NOT the same:

  1. Cohere key   -> turns speech into text  (Settings, first section)
  2. AI chat key  -> answers questions in chat (Settings, second section)

--- Free option: Google Gemini (NO credit card) ---

Google AI Studio gives a free API key with no billing details. You need a
Google account, nothing else.

STEP A. Get the key
  1. Open https://aistudio.google.com/apikey
  2. Sign in with any Google account.
  3. Click "Create API key".
  4. Copy it. It starts with "AIza".

STEP B. Point the app at Gemini
  In the presence folder:

    cp llm_config.gemini.json llm_config.json

STEP C. Put the key in the Terminal
  In the SAME window you will start the server from:

    export GEMINI_API_KEY="AIza-your-key-here"

STEP D. Start the server in that same window
    python3 app.py

--- Other free options ---

* Ollama (fully offline, no key at all): install from ollama.com, run
  `ollama pull llama3`, then set in llm_config.json:
      "base_url": "http://localhost:11434/v1",
      "model": "llama3",
      "api_key_env": "NONE"

* OpenCode Zen: see llm_config.opencode.json. Its free models generally
  require the OpenCode app itself, so they may be refused from a website.

--- How to tell it worked ---

Ask the coach a question. Under the chat it will say either:

  "Answered by your configured LLM endpoint."   -> the key works
  "Answered from your last measurements..."     -> the key did NOT work

Never put a real key inside llm_config.json. That file stores only the NAME
of the environment variable, so it is safe to show anyone.


STOPPING
--------
Press Ctrl + C in the Terminal window.

Closing the Terminal window stops the website too.


IF SOMETHING IS WRONG
---------------------
"Can't connect" / blank page
    The server is not running. Do Step 2 again.

"Address already in use"
    An old server is still running. Find that window, press Ctrl + C.

Microphone blocked
    Click the padlock in the address bar, set Microphone to Allow, reload.

"No key" / transcription skipped
    Open Settings, paste the Cohere key, Save.

Page looks old
    Press Cmd+Shift+R to hard-reload.


RUN THE TESTS  (and see the results)
------------------------------------
Two commands, both print what they did:

  python3 run_all_tests.py       every test, grouped by feature
  python3 run_all_tests.py -v    every individual test name

Expected ending:

  All 221 tests passed (0.99s)

CHECK YOUR CONNECTIONS  (are the services reachable?)
-----------------------------------------------------
  python3 check_connections.py

This makes REAL requests and prints PASS / FAIL for each:

  1. Project files present and importable
  2. Cohere key present AND accepted by Cohere
  3. Arabic transcription model available
  4. Gemini key present AND answers a real question
  5. llm_config.json valid, and its key present
  6. Whether the app server is running on :8080

It never prints a full key - only the last 4 characters - so it is safe to
screenshot for your PDF.

A FAIL means something is genuinely not connected. A SKIP means that part is
optional and you have not set it up, which is fine.
